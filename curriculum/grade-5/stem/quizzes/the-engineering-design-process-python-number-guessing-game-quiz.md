### Questions

**1.** Name the five core steps of the **Engineering Design Process**:
1. **A**___________ (What is the problem? What are the constraints?)
2. **I**___________ (Brainstorm ideas and solutions!)
3. **P**___________ (Draw diagrams, choose materials, plan steps.)
4. **C**___________ (Build your prototype and test it!)
5. **I**___________ (What broke? How can we make it better?)

**2.** Why is failure considered a normal and helpful part of the engineering process?

**3.** Read this Python number guessing game snippet:
```python
secret = 7
guess = int(input("Guess a number (1-10): "))

if guess == secret:
    print("YOU WIN! Incredible guess!")
elif guess < secret:
    print("Too low! Try again!")
else:
    print("Too high! Try again!")
```
If a player inputs `4`, which message will be printed? What does `elif` stand for?

**4.** When testing a newly built paper airplane or bridge prototype, why should an engineer only change **one variable at a time**?

**6.** In Scratch or Python, what is a **bug**? Where does the funny word "computer bug" historically come from?

**7.** **Diagram Challenge:** Sketch a blueprint or flowchart of a new invention you would love to build in your workshop or Minecraft world.

**8.** How do you export and back up your Scratch project file to your computer so your hard work is safe?

## 🔑 Parent Answer Key (For Educator)

<details>
<summary>Click to expand Answer Key</summary>

1. **Engineering Design Process**:
   - Ask, Imagine, Plan, Create, Improve.

2. **Value of Failure in Engineering**:
   - Prototypes fail because they show weaknesses that calculations missed. Finding flaws allows engineers to iterate and make the final design stronger and safer.

3. **Python `elif` Logic**:
   - Since $4 < 7$, it prints: `"Too low! Try again!"`
   - `elif` stands for "else if".

4. **Single Variable Control**:
   - Changing only one variable ensures you know exactly which change caused the improvement or failure.

5. **Scientist vs. Engineer**:
   - "How can we design a solution to solve this problem?" (or "How can we build this?").

6. **History of "Bug"**:
   - A bug is an error, flaw, or glitch in code that causes it to behave incorrectly.
   - In 1947, computer pioneer Grace Hopper's team found a real moth trapped inside the Mark II electromechanical computer relays, taped it in the logbook, and noted they were "debugging" the machine!

7. **Invention Blueprint**:
