# Lesson 05 — Comparing Solutions Fairly

**Time:** 30–35 minutes · **Materials:** drum or upturned pot,
flashlight (adult-handled), index cards, science journal, the Lesson
04 code cards.

**Goal (read to the learner):** Today you will judge two ways of
sending a message against the same rules — *criteria* and
*constraints* — and pick the better one with evidence, not with a
favorite.

**Readiness check:** Adult asks, "If two teams both claim their code is
best, how could we tell who is right?" Any answer about testing both
the same way shows readiness.

## Teaching (adult reads and models)

When engineers compare solutions, they do not ask "which do I like?"
They ask "which meets the **criteria** best, inside the
**constraints**?" Criteria are what a successful solution must do.
Constraints are the limits — materials, time, cost — it must respect.
A solution that fails a constraint cannot win, however clever it is.

Today's comparison uses the same message job for both solutions: send
one of four messages across the room so the receiver writes it down
correctly. The criteria and constraints are agreed *before* testing:

- **Criteria:** (1) the receiver gets the message right; (2) the
  message arrives in under one minute; (3) the receiver can repeat it
  back correctly.
- **Constraints:** (1) no speaking and no walking over; (2) only the
  drum, the flashlight, or paper grids on hand; (3) sound levels stay
  comfortable.

Testing must be fair (Unit 01): same message list, same distance, same
number of trials for each solution, same receiver skill. Change the
solution; keep everything else the same. Record every trial, including
the failures — a solution tested only on its best day is not honestly
tested.

**Worked example 1 — reading a results table (fictional practice data)**

> Adult thinks aloud over this table, labeled clearly as practice
> data, not results the learner measured:
>
> | Solution | Trial 1 | Trial 2 | Trial 3 | Correct of 15 messages* |
> |---|---|---|---|---|
> | Drum code (sent twice each time) | 4 of 5 right | 5 of 5 right | 4 of 5 right | 13 |
> | Flashlight code (long/short flashes) | 3 of 5 right | 4 of 5 right | 4 of 5 right | 11 |
>
> *\*Each trial sent 5 messages; 3 trials = 15 messages per solution.*
>
> *"The drum code got 13 of 15 right; the flashlight code got 11 of
> 15. 13 is more than 11, so on accuracy the drum code wins. But wait
> — check the constraints too. Did either solution break a rule? Both
> stayed silent, both used materials on hand, both finished in under
> a minute. So the drum code wins this comparison on the stated
> criteria, and the reason is the numbers: 13 beats 11. If the
> flashlight team had shouted the answers, their trials would not
> count at all — breaking a constraint disqualifies the trial, not
> just lowers its score."*

**Worked example 2 — one change, or the comparison fails**

> Adult models the error: *"Suppose the drum team sends easy messages
> ('come,' 'stop') while the flashlight team sends hard ones, and the
> drum team stands closer to the receiver. Now the drum team's win
> proves nothing — two things changed at once: the message difficulty
> AND the distance. That is the unfair-test error from Unit 01, wearing
> a new coat. A fair comparison changes only the solution. Same
> messages, same distance, same trials. Otherwise the table compares
> luck, not solutions."*

Key idea to say plainly: **Agree on criteria and constraints first.
Test every solution the same way. The winner is the one the evidence
names — and a solution that breaks a constraint cannot win.**

## Guided practice (adult leads, learner answers and does)

1. Read the fictional table in Worked Example 1 again. Which solution
   is more accurate, and by how many messages?
2. A third solution — shouting the message — gets 15 of 15 right.
   Does it win? Use the constraints to explain why or why not.
3. Name one criterion and one constraint for this new job: "Send a
   message to someone in the next room without entering it."
4. Fix this unfair comparison: "Team A tested in a quiet room, Team B
   tested while music played, and Team A won." What must change?
5. A solution fails its first trial but passes the next two. Should
   the failure be erased from the table? Why does honest recording
   matter for the final recommendation?

## Independent practice

1. Two solutions are tested fairly, 3 trials of 5 messages each.
   Solution P: 5, 4, 5 right. Solution Q: 3, 5, 4 right. Totals? Which
   is more accurate? By how many messages?
2. Write one criterion and one constraint for a code that must work
   in a dark room. (Hint: a light-flash code needs light; a drum code
   does not.)
3. A team changes its code card halfway through testing because the
   old code "was not working." Explain why all earlier trials must
   now be re-run, not kept.
4. Your solution gets every message right but takes 3 minutes, and the
   criterion says "under 1 minute." Does it meet the criteria? What
   should the team do next: claim victory, or improve speed and retest?
5. Explain in two sentences why engineers test more than one solution
   instead of building the first idea that comes to mind.

## Applied task

Run a mini-comparison now: drum code versus flashlight code, same
four messages, same distance, 2 trials of 4 messages each (8 messages
per solution). Record every result in a table, total the correct
messages, and write a one-sentence recommendation that names the
winner and the numbers that support it. This is the rehearsal for the
project's full comparison.

## Exit check

Learner states one criterion, one constraint, and one rule of fair
comparison, each in their own words, without looking at the journal.

## Supports and extensions

- **Support:** use a pre-drawn criteria table with picture symbols
  (a checkmark for "got it right," a clock for "under one minute") so
  judging does not depend on reading long sentences.
- **Extension:** add a second criterion — "the receiver can use it
  without seeing the sender" — and re-judge both solutions. Does the
  winner change? Explain why a new criterion can change a verdict.

## Teacher note

Likely misconception: the fastest or loudest solution is "best"
regardless of accuracy. The table work exists to anchor judgment in
the agreed criteria, in order: constraints first (disqualifiers), then
criteria scores. Also watch for learners deleting failed trials —
treat honest failure recording as a graded habit in the project
rubric, not as a punishable mistake. Answer-key reference:
[answer-key.md](../answer-key.md), Lesson 05. Note the totals in
Worked Example 1: drum 4 + 5 + 4 = 13 of 15; flashlight 3 + 4 + 4 =
11 of 15.
