# Lesson 04 — Patterns Carry Information

**Time:** 30–35 minutes · **Materials:** drum or upturned pot,
flashlight (adult-handled), grid paper or printed 5-column grids,
pencils, index cards, science journal.

**Goal (read to the learner):** Today you will send messages without
speaking, using only patterns — drum rhythms, picture grids, and tap
codes — and find out why the pattern, not the thing, carries the
message.

**Readiness check:** Adult asks, "If you could not speak or walk over,
how could you tell someone across the room to come here?" Any pattern
idea (waving, tapping, flashing) shows readiness.

## Teaching (adult reads and models)

A **code** is an agreed pattern that stands for a message. The sender
and the **receiver** must agree on the code *before* the message is
sent; otherwise the pattern is just noise. Three codes from the
standard itself show the idea:

- **Drum code:** long and short beats stand for different messages.
  Agree first: one beat = "come," two beats = "stop," three beats =
  "look," four beats = "help." The drum does not travel to the
  receiver — the *pattern of beats* travels as sound waves.
- **Picture grid code:** a grid of 1's and 0's stands for a picture.
  Agree first: 1 = a filled (black) square, 0 = an empty (white)
  square. Fill the 1's, and a picture appears — even though no picture
  itself was sent, only numbers.
- **Tap code:** short taps (dots) and long taps (dashes) stand for
  letters, the way Morse code sends text. Agree on a few letters
  first; nobody is expected to memorize a whole alphabet.

In every case, the pattern is the message. Change the pattern and you
change the message, even if the drum, the paper, and the people stay
exactly the same.

**Worked example 1 — drumming a message**

> Adult thinks aloud: *"Our code is on the card: 1 = come, 2 = stop,
> 3 = look, 4 = help. I want to send 'help.' I drum four beats: boom,
> boom, boom, boom. The receiver counts four and reads the card: help.
> Now suppose I drum three beats by mistake. The receiver reads 'look'
> — a different message — even though I meant help. That is why codes
> need a check: the receiver should repeat the message back, or the
> sender should send it twice. A pattern only works when both sides
> share it exactly."*

**Worked example 2 — reading a picture grid**

> Adult models with the grid below, row by row: *"1 means fill the
> square, 0 means leave it empty. Row 1: 1 1 1 1 1 — a full row of five
> filled squares. Rows 2, 3, and 4: 0 0 1 0 0 — only the middle square
> filled. Put them together: a bar across the top and a stem down the
> middle. That is the letter T. I never sent a letter. I sent five rows
> of numbers, and the receiver rebuilt the picture. If one number in
> row 1 were wrong — 1 1 0 1 1 instead — the top bar would have a gap,
> and the picture would be wrong. One changed number changes the
> message."*

```
Row 1:  1 1 1 1 1
Row 2:  0 0 1 0 0
Row 3:  0 0 1 0 0
Row 4:  0 0 1 0 0
```

Key idea to say plainly: **A code is a pattern both sides agree on.
The pattern travels; the message is rebuilt at the other end. One
changed beat or number changes the message.**

## Guided practice (adult leads, learner answers and does)

1. Drum relay: the adult drums a code number (1–4) from the agreed
   card; the learner names the message. Swap roles and repeat twice.
2. Decode the T grid above on grid paper, coloring the 1's. What
   letter appears? What would row 1 look like if the message were
   the letter I instead? (Think: a stem with no top bar — but the
   receiver would need the code card to know.)
3. Tap code: agree on dot = short tap, dash = long tap, and the code
   dot-dot = "yes," dash = "no." The adult taps; the learner answers
   the question "Are you ready?" with the matching taps.
4. A sender drums "come" (1 beat) but the receiver hears 2 beats and
   reads "stop." Who is at fault — the code, the sender, or the
   hearing? What check would have caught the error?
5. Name one pattern from everyday life that carries information
   without words (traffic lights, a doorbell pattern, a whistle
   signal, a flag) and say what each pattern means.

## Independent practice

1. Write the drum-code card for four messages of your own choosing
   (for example: 1 = "water," 2 = "finished," 3 = "again," 4 =
   "danger"). Keep the same code for the whole unit — changing it
   mid-unit breaks every earlier message.
2. Decode this grid. What picture does it make?
   Row 1: 1 0 0 0 1; Row 2: 1 0 0 0 1; Row 3: 1 1 1 1 1; Row 4: 1 0 0 0 1.
3. Encode the letter L on a 4-row, 5-column grid of 1's and 0's.
   (Hint: a stem on the left and a foot along the bottom row.)
4. A friend says, "The drum itself carries the message across the
   room." Explain the mistake: what actually travels, and what stays
   where it is?
5. Two teams use the same drum code. Team A sends each message twice;
   Team B sends each message once. Which team's messages are more
   likely to arrive correctly, and why?

## Applied task

Send a real message across the room without speaking or walking over:
choose either the drum code or the tap code, send one of the four
agreed messages, and have the receiver write down what they received
before you tell them what you sent. Record: sent, received, match or
mismatch, and one reason for the result. Repeat three times.

## Exit check

Learner decodes one new 4-row grid shown by the adult and states, in
one sentence, why the pattern — not the paper or drum — is what
carries the information.

## Supports and extensions

- **Support:** use color instead of numbers for the grid (color the
  1-squares, leave the 0-squares blank) and use picture cards for the
  drum messages, so reading is not required to send or receive.
- **Extension:** design a code that can send a whole word, using
  dot/dash taps for three letters you choose. Write the code card,
  send the word, and have the receiver decode it. Report any letter
  that failed and why.

## Teacher note

Likely misconception: "the thing carries the message" (the drum, the
paper, the light). Every activity in this lesson separates the carrier
from the pattern: same drum, different beat, different message. Also
watch for learners inventing a new code mid-activity — gently enforce
the agreed card, because a code that changes without telling the
receiver is a broken code, and that failure is itself worth naming.
