# Lesson 05 — Design Problems and Investigation Reports

**Time:** 30–35 minutes · **Materials:** science journal, pencil, the
paper-towel project data so far, the investigation-report skeleton (see
Teaching).

**Goal (read to the learner):** Today you will learn how scientists turn a
problem into a **design problem** — with criteria and constraints — and you
will learn the **investigation report** format the whole year will use.

**Readiness check:** Adult asks, "What is the one rule of a fair test?"
One change, everything else the same, repeated trials.

## Teaching (adult reads and models)

Sometimes science answers a question. Sometimes it **solves a problem** —
and then we define a **design problem**: a need or want plus **criteria**
(what a successful solution must do) and **constraints** (limits on
materials, time, or cost). (This is 3-5-ETS1-1, the engineering idea this
year's Unit 08 capstone will reuse.)

- *"We need a way to clean up spills in the kitchen."* Criteria: soaks up at
  least 100 mL; does not fall apart when lifted. Constraints: uses only the
  paper towels we already have; must be testable in one afternoon.
- Notice what the criteria did: they turned "a good towel" into something
  **measurable** — milliliters held, tears or not. Good criteria are
  measurable; good constraints are honest about limits.

Then scientists **report** what they did so anyone can check it. Our
investigation-report format (adapted for grade 4 from the repository's
lab-report template) has six parts:

1. **Question** — the testable question.
2. **Plan** — the one change, the controls, the number of trials, the
   measurement and its unit, one failure point and its prevention.
3. **Data** — the labeled table with every trial.
4. **Display** — the bar graph, pictograph, or line plot (title, labels,
   unit).
5. **Claim** — what the evidence shows, supported by at least two data
   values, plus one limitation.
6. **Design connection (optional)** — if this were a design problem, what
   would the criteria and constraints be?

**Models, one more time:** your labeled diagram from Lesson 01 and your
graph from Lesson 04 are both **models** — representations that help explain
something real. In Unit 03 you will meet two new model words: **amplitude**
(how tall a wave is) and **wavelength** (the spacing between wave peaks).
You already know the idea: a model shows the pattern so you can talk about
it.

**Worked example 1 — design problem, defined**

> Adult thinks aloud: *"Problem: our classroom plants get overwatered —
> water sits in the saucers. Design problem: build a plant-watering checker.
> Criteria: tells 'too wet,' 'just right,' or 'too dry' using something we
> can observe; costs nothing new. Constraints: only materials in the tool
> tray; must work within one week. See how the criteria are observable and
> the constraints are honest? That is a defined design problem."*

**Worked example 2 — a report skeleton, filled**

> Adult fills the skeleton with the fictional brand-B dataset from Lesson
> 04: *Question: which brand holds the most water? Plan: change = brand;
> controls = same 100 mL poured, same wait time, same tray; trials = 3;
> measure mL held; failure point = towel tears → support from below. Data:
> table with all trials. Display: bar graph. Claim: 'Brand B held the most
> water — about 55 mL per trial, about 16 mL more than brand C. Limitation:
> we tested only one package of each brand.'* Six parts, each checkable.

Key idea to say plainly: **A design problem names what success looks like
(criteria) and what limits you (constraints). A report shows your question,
plan, data, display, and claim so anyone can check your work.**

## Guided practice (adult leads, learner defines and drafts)

1. Turn this into a design problem: "We need a container that keeps an ice
   cube from melting." Learner names two measurable criteria and two
   constraints. *(e.g., criteria: ice still solid after 30 minutes;
   container fits in a lunchbox; constraints: only recycled materials; one
   class period to build)*
2. "Which of these is a constraint: 'must hold 200 mL' or 'must use only
   classroom materials'?" *(the second — a limit; the first is a criterion)*
3. Fill the report skeleton's Question and Plan for the paper-towel
   project.
4. "Why does the report include a limitation?" *(honest science names what
   the test cannot prove)*

## Independent practice

The learner completes the report skeleton for the paper-towel investigation
with their own Question, Plan, Data (from Session 10), Display, and a draft
Claim. Sentence frame: "My claim is ___ because the data show ___ and ___.
One limitation is ___."

## Application

Pick a household problem (lost socks, spilled cereal, a wobbly table). Write
it as a design problem: one need, two measurable criteria, two constraints.

## Exit check

Prompt: "Name the six parts of the investigation report." Accept: question,
plan, data, display, claim, design connection (the last optional). Any order
is fine if all six are named.

## Supports and extensions

- **Support:** Adult scribes the learner's spoken answers into the skeleton.
- **Extension:** The learner writes a design problem for Unit 03's
  information-transfer challenge (send a message across the room with no
  talking): criteria = message arrives correctly, constraints = no voices,
  only classroom materials — pre-seeding 4-PS4-3's solution comparison.

## Teacher note

**Likely misconception:** criteria and constraints are the same thing.
Re-anchor: criteria = what success *does* (measurable); constraints = what
limits you (materials, time, cost). Watch for unmeasurable criteria ("works
well") — push for a number or an observable. **Answer-key reference:**
[answer-key.md](../answer-key.md) (Lesson 05).
