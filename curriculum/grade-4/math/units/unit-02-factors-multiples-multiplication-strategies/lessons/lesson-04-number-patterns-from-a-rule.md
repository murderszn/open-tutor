# Lesson 04 — Number Patterns from a Rule: Find What the Rule Didn't Say

**Session:** 9 · **Time:** 35 minutes · **Goal:** I can generate a number
pattern from a given rule, identify a feature of the pattern that the rule
never stated, and explain informally *why* that feature keeps happening.

**Materials:** paper and pencil, crayons (two colors), a number line strip
optional.

## Readiness check (4 min)

Retrieval warm-up from Unit 01: estimate 7,248 − 3,911 to the nearest thousand
(7,000 − 4,000 = 3,000), then ask: "Will the exact answer be odd or even?"
(Learners reason from the estimate: 7,248 is even, 3,911 is odd, even − odd =
odd.) If the parity rule is shaky, test 6 − 3 and 5 − 2 together first.

## Explicit teaching (10 min)

A **pattern** is a list of numbers (or shapes) built by a **rule** — a repeat
instruction. Each number in the list is a **term**. Generating the pattern is
easy: just follow the rule. The interesting work is step two: look at what
you made and notice features the rule *never mentioned* — then explain *why*
they happen.

The standard's own example — rule **"Add 3"**, start at **1**:

1, 4, 7, 10, 13, 16, 19, 22, …

Read the rule: it says nothing about odd or even. But look: odd, even, odd,
even, odd, even… The terms **alternate**. Why? Because 3 is **odd**, and
adding an odd number always flips parity: odd + odd = even, even + odd = odd.
Every step flips, so the pattern alternates forever — not just for the terms
we wrote.

The full routine for this lesson:

1. **Generate** — write at least 8 terms by following the rule exactly.
2. **Inspect** — color-code or label features (odd/even, tens digits,
   divisibility) and name one feature not in the rule.
3. **Explain** — write one or two sentences on *why* the feature continues
   ("informally" — kid-reasoning, not a proof).

## Worked example 1 — Rule "Add 3", start 1 (the alternation)

1. Generate: 1, 4, 7, 10, 13, 16, 19, 22.
2. Inspect: label O/E: O, E, O, E, O, E, O, E — strict alternation. Hidden
   feature: odd/even alternation.
3. Explain: "3 is odd. Adding an odd number flips a number from odd to even
   or even to odd every time. So the terms must keep alternating — the 100th
   term will be even (since term 1 is odd and every odd-numbered term stays
   odd)." ✓

## Worked example 2 — Rule "multiply by 2", start 3

1. Generate: 3, 6, 12, 24, 48, 96, 192, 384.
2. Inspect: label O/E: O, E, E, E, E, E, E, E. Hidden feature: *after the
   first term, every term is even* — the rule said nothing about evenness.
3. Explain: "Multiplying any whole number by 2 gives an even number (it is 2
   groups of the number — every number × 2 is even). The first term, 3, is odd
   because we started there, but from 6 on, the rule forces evenness
   forever." ✓

## Guided practice (with hints)

Work through these together; the adult gives the hint, the learner does the
writing.

1. Generate 8 terms: rule "Add 5", start 2. *(Hint: label each term O or E
   as you go.)*
2. Name a hidden feature of your "Add 5" pattern and explain why it continues.
   *(Hint: is 5 odd or even? What did adding 3 do?)*
3. Generate 7 terms: rule "Add 10", start 4. What hidden feature do you see?
   *(Hint: look at the ones digits — and compare with the "Add 3" pattern.)*
4. **Predict:** in the "multiply by 2, start 3" pattern, will the 20th term
   be odd or even? *(Hint: use your explanation from Worked Example 2, not
   the list.)*

## Independent practice

5. Generate 8 terms: rule "Add 4", start 1. Identify a hidden feature and
   explain it. (Different from "Add 3" — why?)
6. Generate 6 terms: rule "multiply by 3", start 2. Identify a hidden
   feature and explain it.
7. A learner generates "Add 6, start 5" as 5, 11, 17, 23, 29, 35 and says the
   hidden feature is "they're all odd." Agree? Explain why this must continue.
8. **Explain your reasoning:** the rule is "Add 2", start 7. Without writing
   all terms, what can you say about the 50th term? Defend your answer.

## Application

Pattern journalist: invent your own rule (addition or multiplication by a
one-digit number) and a starting number. Generate 10 terms, find one hidden
feature, and write the informal explanation as if for a newspaper "math
mystery" column. Trade with the adult: can they verify your explanation?

## Exit check

Rule "Add 9", start 2: generate 6 terms, name one hidden feature, and write
the informal explanation in one or two sentences.

## Supports

- **Reading/language access:** read each rule as a recipe ("take the number,
  add 3, write it down, repeat"); label O/E with colored dots rather than
  letters.
- **Alternate response mode:** the learner may generate terms by skip-counting
  aloud with claps and dictate the hidden feature while the adult scribes.
- **Extension:** rule "Add 3, start 2" — does it alternate? Starting parity
  matters. Prove the 1,000th term's parity for "Add 3, start 1" two ways
  (alternation argument and formula: term n = 1 + 3(n−1) = 3n − 2, even when
  n is even). Then: for which starting numbers does "Add 4" keep everything
  odd?

## Teacher note

Likely misconception: stating the rule back as the "feature" ("the pattern
goes up by 3" — that *is* the rule, not a hidden feature). Reteach: the
hidden feature must be something you could only see *after* generating —
parity, digit patterns, divisibility. Another: explanations that only describe
("it keeps alternating because the numbers alternate") — push to the *cause*
(adding an odd number flips parity). Accept informal causal language; do not
demand proof vocabulary.
