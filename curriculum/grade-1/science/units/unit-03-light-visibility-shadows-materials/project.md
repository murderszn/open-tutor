# Project — The Flashlight Message Device

**Sessions 12 and 14 (plus Lesson 04 planning in Session 11 and Lesson 05
comparison in Session 13).** Adult-supervised throughout. The learner's
plan sketch from Lesson 04 is the starting point; this project is the
build, test, and compare.

## The problem

Send a message across the room without speaking, without walking over,
and without any sound at all. The receiver must understand the message
from light alone.

## Materials

- Two flashlights (sender's + spare), a dim room, a white wall
- The written code list from Lesson 04 (1 flash = "yes", 2 flashes =
  "come here", 3 flashes = "lunchtime" — or the learner's own agreed code)
- The Unit 02 sound device (cup-string telephone or tap code) for the
  Session 14 comparison
- Journal for the plan sketch and the comparison table
- Optional bonus: a small mirror on a stand for a "bounce around the
  corner" test

## Steps

### Part 1 — Build from the plan (Session 12)

1. **Re-read the plan.** The learner shows the Lesson 04 sketch: sender,
   flashlight beam, wall, receiver, code list. "What are you building?"
2. **Set the stage.** Sender at one side of the room, receiver at the
   other, wall between them in the receiver's view. Tape the code list
   where the receiver can see it.
3. **First test.** The sender sends one message (the receiver picks which
   one to request: "Send me 'come here'"). The receiver reads it from the
   wall and says what it means. Record: got through? yes/no.
4. **Fix what failed.** If a message failed (too fast, flashes blurred
   together, receiver not watching the wall), change ONE thing and test
   again: slower flashes, a longer pause between flashes, or the receiver
   moving closer to the wall. Record the change.
5. **Distance test.** Move the sender farther back in two steps. At each
   step, send "yes." Record: did it still get through? (Light crosses
   the room; the message should survive distance — unlike a whisper.)

### Part 2 — Test two designs and compare (Session 14)

1. **Same message, same distance, two devices.** Send "come here" by
   light, then by the Unit 02 sound device, from the same spot.
2. **Three conditions.** Test both devices in: (a) a quiet dim room,
   (b) a noisy room (gentle clapping or soft music), (c) a bright room
   (lights fully on) — plus, if time allows, (d) a receiver facing away
   from the wall.
3. **Fill the comparison table.** For each device × condition: tick
   (got through) or cross (did not get through). Star the winner of each
   condition.
4. **Judge with conditions.** The learner finishes: "The light messenger
   is better when ___. The sound messenger is better when ___." (No
   device wins everywhere.)
5. **Bonus (optional).** Mirror bounce: can a message go around a corner
   with a mirror? Test once and record honestly — a failed bonus test is
   still good science.

## Deliverables

1. The plan sketch (from Lesson 04, kept with the project).
2. The written code list (sender and receiver agreed, adult-scribed).
3. The test record: first test, one fix, distance test (Part 1).
4. The comparison table: 2 devices × 3 conditions with winners starred
   (Part 2).
5. The learner's judgment sentence with conditions (Part 2, step 4).

## Rubric

Observable criteria, adult-scored. Each criterion: **Secure (2)**,
**Developing (1)**, **Not yet (0)**. Total out of 8.

| Criterion | Secure (2) | Developing (1) | Not yet (0) |
|---|---|---|---|
| **Plan → build** | Builds from the sketch; the built device matches the plan's parts (sender, beam, wall, receiver). | Builds with heavy adult re-planning; parts missing but device attempted. | No connection between sketch and build. |
| **Code use** | Sends and reads at least 2 of 3 code signals correctly from the wall. | Reads 1 signal correctly, or needs the adult to re-read the code list each time. | Cannot read signals from the wall. |
| **Fair comparison** | Tests both devices on the same message and distance across all 3 conditions; table matches what happened. | Tests both devices but changes message or distance between them, or misses a condition. | Tests only one device, or table does not match the tests. |
| **Condition-based judgment** | States which messenger wins per condition with a test-based reason; says neither wins everywhere. | Names a winner but without a condition, or without a reason. | Claims one device is best everywhere, or gives no judgment. |

**Readiness signal:** 6–8 with no zero = ready to move on. 4–5 = ready
with a re-teach of the lowest criterion (usually the comparison table —
re-run one condition together). 0–3 = re-teach the code and the fair-test
idea (Lessons 04–05) in a flexible week before Unit 04.

## Safety

Flashlight beams point at the wall, never at eyes. The receiver watches
the wall, not the sender. String from the Unit 02 telephone is
adult-handled and never around a neck. Noise conditions stay gentle.
