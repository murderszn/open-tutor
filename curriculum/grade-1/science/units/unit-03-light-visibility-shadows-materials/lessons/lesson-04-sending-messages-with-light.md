# Lesson 04 — Sending Messages with Light

**Student goal:** I can agree a flashlight code and draw a plan for a
light messenger that sends a real message across the room.
**Time:** 20–25 minutes · **Unit:** [U03](../README.md) · **Session 11 of 16**

## Materials

- Two flashlights (one for the sender, one spare)
- A darkened corner or a dim room and a white wall to flash against
- Science journal, crayons (for the plan sketch)
- The Unit 02 device (cup-string telephone or tap code) nearby for
  reference — not used until Lesson 05

**Safety note for the adult:** flashlight beams point at the wall — never
at eyes, never at faces. The receiver watches the WALL, not the sender.
Codes are short (three signals) so the receiver can remember them.

## Readiness check (2 minutes)

"In Unit 02 we sent messages with sound — a telephone made of cups, or
taps. Could we send a message with NO sound at all? What could we use
instead?" (Light flashes! A wave, a flag — accept any sensible answer;
steer to flashes.) If the learner can name one no-sound signal, begin.

## Teaching

To **communicate** is to send a message so someone else gets it. A
**device** is a tool you build to solve a problem. Our problem: send a
message across the room without speaking and without walking over.

A **signal** is one flash (or sound) that means something. A **code**
is a set of signals we agree on BEFORE sending. Without agreement, a flash
is just a flash. With agreement, a flash means "yes."

Here is our code — we agree it together, and we write it down:

- **1 flash = "yes"**
- **2 flashes = "come here"**
- **3 flashes = "lunchtime"** (or any third message the learner picks)

Before building, we **plan**: we **sketch** — a quick drawing of the
idea. The sketch shows: the sender with the flashlight, the wall where
flashes land, the receiver watching the wall, and the code list. A plan
first, then a build — that is the Unit 02 design cycle again.

## Worked example 1 — sending "yes" (modeled)

The adult is the sender; the learner is the receiver, watching the wall.

> "Our code says 1 flash = yes. I will ask you a question with my
> voice — 'Do you want to play the shadow game?' — and answer it with
> light only. Watch the wall."
>
> The adult flashes once on the wall. "What did I send? One flash. Our
> code says one flash means…?" (Yes!) "You read a message made of light.
> No sound carried it. The light did."

**Reasoning to name aloud:** the message worked because we agreed the
code first. The flash alone meant nothing until we gave it meaning.

## Worked example 2 — sending "come here," and a wrong-code check (modeled)

> "Now I send two flashes. What does our code say two flashes mean?"
> (Come here!) "So what should you do? Come here! The message told you
> what to do, and you did it."
>
> "Now — what if I flash four times? Our code has no four-flash message.
> Is that a message?" (No — it is not in our code. The receiver cannot
> know what it means.) "A code only works for signals we agreed on. That
> is why we write the code down."

**Reasoning to name aloud:** a receiver who guesses is not receiving.
Agreed signals, written down, are what make a device a messenger.

## Guided practice (adult stays close, hints allowed)

Do 4–6 short rounds. Offer choices; never demand a spoken answer.

1. Code-read round: the adult flashes 1, then 2, then 3 (pausing between).
   The learner says or points to the matching message card after each.
   *(1 = yes; 2 = come here; 3 = lunchtime.)*
2. Sender round: the learner sends "yes" (1 flash) to the adult, who
   watches the wall and answers aloud. Swap roles once.
3. Error-analysis round: the adult flashes 2 flashes, then claims: "I
   sent 'lunchtime'!" Ask: "Is that right?" *(Expected: no. Two flashes
   mean 'come here' in our code; 'lunchtime' is three flashes. The code
   list decides, not the sender's claim.)*
4. Distance round: the learner stands at the far side of the room and
   sends "come here." "Did the message get through from far away?"
   *(Yes — light crosses the room.)* "Would a whisper get through from
   there?" *(No — that is why a device helps.)*
5. New-message round: "Invent a fourth message for our code — what
   should 4 flashes mean? Write it (adult scribes) on the code list."
   *(Any sensible message counts; the code list is updated.)*
6. If the learner is verbal: "Finish the sentence: a code works because
   we ___ before we send." *(Agree what each signal means.)*

## Independent practice

The learner draws the messenger plan in the journal: sender, flashlight
beam, wall with flashes, receiver, and the 3-signal code list (adult
labels from dictation). The adult sits nearby and observes: does the
sketch show all four parts (sender, light, wall, receiver)? When finished,
the adult asks, "What will you build from this plan tomorrow?" and scribes
the answer for private storage.

*Alternate response mode:* the learner arranges four picture cards in
order (sender → flashlight → wall flashes → receiver) and points to the
code list, or dictates the plan while the adult draws.

## Application

"Show someone at home the code list. Send them one message with a
flashlight tonight (beam on the wall, never at eyes). Tomorrow, tell me:
did they understand it?" (In a one-on-one setting, the learner reports
back at the next session.)

## Exit check

The adult flashes a code (1, 2, or 3) on the wall and asks: "What did I
send? How do you know?" Then: "Show me your plan sketch. What will you
build from it?" The learner should read at least two of three codes
correctly and explain the sketch's parts (words, pointing, or mime). The
adult records: secure / developing / not yet. A second probe: "Why do we
write the code down?" (So sender and receiver agree counts.)

## Supports

- **Language access:** teach "signal" and "code" by doing first (flash,
  then name it). Message cards carry a picture (tick, footprints, lunch
  box) beside the flash count. Accept home-language words alongside English.
- **Alternate response mode:** pointing to message cards, holding up
  fingers for the flash count, drawing the plan.
- **Floor-play variant:** sender and receiver sit on the floor at opposite
  ends; flashes land on a big paper sheet between them.
- **Seated-table variant:** use a small white paper screen on the table
  and short, dim-room flashes.

## Extension

"Could we send a message with light around a corner?" (Not directly — the
beam goes straight. A mirror could bounce it around the corner — preview
of the reflective material from Lesson 02. Accept any sensible answer;
the project may test a mirror bounce as a bonus.)

## Teacher note

**Likely misconceptions:** (1) "any flash is a message" — only agreed
signals count; (2) "the receiver should watch the sender" — the receiver
watches the WALL, where the signal lands; (3) "louder/brighter is always
better" — brightness does not change meaning; the COUNT does.
**Safety:** re-check beam discipline before every sending round.
