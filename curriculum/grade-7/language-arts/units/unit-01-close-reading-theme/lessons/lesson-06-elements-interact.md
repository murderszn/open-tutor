# Lesson 06 — How Story Elements Interact: The Interaction Map

**Student goal:** I can map how plot, character, setting, and conflict push
on each other, and show how theme emerges from their interaction.
**Time:** 40–50 minutes · **Unit:** [U01](../README.md) · **Session 11 of 16**
**Standard:** RL.7.3

## Materials

- "The Lantern on Greyrock Point" (Lesson 01)
- Notebook or large paper for the map

## Readiness check (5 minutes)

Ask the learner to name the five story elements and one fact about each for
our story (character: Mara; setting: storm-night lighthouse; plot: she
keeps the lamp lit against orders; conflict: person vs. nature, vs.
authority, vs. self; theme: duty outweighs obedience). If any element is
shaky, revisit the literary-terms guide's story-elements section with the
adult before continuing.

## Teaching

Stories are systems: each element pushes on the others, often in **both
directions** (two-way arrows).

- Setting → character: the gale forces Hale's order and Mara's crawl.
- Character → setting: Mara *changes* the setting's meaning — the lamp
  room goes from "forbidden place" to "her post."
- Character → plot: Mara's decision to disobey *is* the rising action.
- Plot → character: surviving the gallery walk proves to Hale (and Mara)
  that she is ready — the badge (¶12) marks her change from granddaughter
  to keeper.
- Conflict → theme: the person-vs.-authority conflict *is* the machine that
  manufactures the theme "responsibility outweighs obedience." No conflict,
  no theme.

An **interaction map** makes this visible: put the five elements in boxes
(or a circle), draw arrows between the ones that affect each other, and
**label every arrow with the mechanism** ("forces," "tests," "reveals,"
"confirms") plus a paragraph citation. An unlabeled arrow is decoration; a
labeled arrow is analysis.

Theme **emerges** from the whole system: it is the message the *interactions*
produce. That is why Lesson 03's theme statement needed the ending — the
ending is where the interactions deliver their verdict.

**Key vocabulary:** *interact* (mutual influence), *mechanism* (the
specific way one element affects another), *emerge* (to arise from the
combination, not from any single part).

## Worked example 1 — a labeled two-way arrow

The adult draws and thinks aloud:

> "Boxes: SETTING (gale, icing gallery) and CHARACTER (Hale). Arrow one,
> setting → character, labeled '**forces**: the ice forces Hale to forbid
> the gallery (¶5).' Arrow two, character → setting, labeled '**redefines**:
> Hale's order turns the lamp room from 'workplace' into 'forbidden place'
> for Mara — the same physical space now carries a rule. Two arrows, two
> different mechanisms, both cited. Notice the arrows are not the same: one
> is physical causation, the other is social meaning. Labeling the mechanism
> is what makes this analysis instead of decoration."

**Reasoning to name aloud:** I checked both directions separately instead of
assuming influence runs one way. Most element pairs interact both ways if
you look closely.

## Worked example 2 — theme emerging from the system

> "Question: where does the theme 'duty outweighs obedience' *come from*?
> Not from any single element. Trace it: the SETTING (leak + gale) creates a
> CONFLICT (obey vs. save the ship); the CHARACTER (Mara) resolves it by
> choosing the lamp; the PLOT (the *Alder* survives) *confirms* the choice;
> the final badge scene *states* Hale's verdict. The theme emerges from the
> chain setting → conflict → character choice → plot outcome → resolution.
> Remove any link — no leak, no dilemma, no disobedience, no badge — and the
> theme has nothing to stand on. That is what 'analyze how elements
> interact' means: show the machine, not just the parts."

**Reasoning to name aloud:** I answered "where does the theme come from"
with a causal chain across four elements, each cited — the full RL.7.3
move.

## Guided practice

With the adult, build the interaction map's first two arrows: CHARACTER
(Mara) ↔ PLOT (the climb). Label each arrow with a mechanism and a
paragraph citation. The adult draws; the learner dictates the labels.

## Independent practice

1. Complete your interaction map: five element boxes, at least **six
   labeled arrows** (mechanism + citation on each).
2. Write a paragraph: "The theme ___ emerges from the interaction of ___
   and ___ because ___." Use at least two academic verbs (*reveals*,
   *conveys*, *suggests*, *develops*).
3. **Error analysis:** A classmate's map has twelve arrows but no labels.
   Explain in two sentences why the map is decoration, and label two of the
   arrows correctly.

## Application

Draft the **portfolio theme statement** for this story (Session 16
deliverable): one theme sentence plus the three-stage development trace
from Lesson 03, now upgraded with one interaction-map insight ("the theme
emerges because ___ interacts with ___"). File it for revision in Week 6.

## Exit check

"Draw two boxes — SETTING and THEME — and connect them with a labeled,
cited arrow. Then add the one element that sits *between* them in the causal
chain." Secure = arrow labeled with a mechanism and citation, middle
element named (conflict or character choice) with a reason; Developing =
arrow present but mechanism vague; Not yet = boxes with no arrow.

## Supports and extension

- **Starter arrows:** setting → character ("forces"), character → plot
  ("decides"), plot → character ("changes"), conflict → theme ("produces").
- **Build physically:** write elements on cards and arrange them on the
  table before drawing.
- **Extension:** add a sixth box — POINT OF VIEW (third-person limited,
  close to Mara). Draw its arrows: how would the theme change if the story
  were told from Hale's point of view? (Preview of U02.)

## Teacher note — likely misconceptions

Maps drift into plot summaries with boxes — require every arrow to name a
*mechanism*, not an event. Learners also draw one-way arrows everywhere;
prompt "does it push back?" for each pair. Finally, some learners treat
theme as a sixth box equal to the others — correct gently: theme is the
*output* of the system, drawn differently (a banner, not a box). Answer-key
reference: [answer-key.md](../answer-key.md) § Lesson 06.
