# Lesson 05 — From Problem to Prototype: Defining a Magnet Design Problem

**Time:** 25–30 minutes · **Materials:** small cardboard box with a
lid, two bar magnets, tape, string, science journal, pencil

**Goal (read to the learner):** Today you will learn how scientists
and engineers turn an idea into a testable plan: **define** a simple
problem, write **criteria** for what counts as success, name the
**constraints**, and build a first **prototype** to test.

**Readiness check:** Adult asks, "You know magnets can hold things
shut and push things apart. What is one problem at home a magnet could
solve?" Any problem naming a magnet use (a box that pops open, two
toys that bump) shows readiness.

## Teaching (adult reads and models)

A design problem starts with a **need**: something that should happen
but does not. "My box lid keeps popping open" is a need. Scientists
then **define** the problem in one clear sentence: "Design a latch
that keeps this box shut when the box is tipped, using magnets."
That sentence names the job and the tool — magnets — and nothing else.

Next come **criteria**: what a good solution must do. Criteria are
testable, so you can check them. For a magnet latch, good criteria are:

1. The lid stays shut when the box is tipped upside down.
2. The lid opens when an adult pulls it with one hand.
3. The latch uses only the magnets, tape, and string allowed.

Then come **constraints**: the limits. "Only two magnets," "no glue,"
"must fit inside the box lid," "build it in 20 minutes" — those are
constraints. Criteria say what success looks like; constraints say
what you cannot do on the way there.

Finally, build a **prototype**: a first test version, made to be
tested and improved — not a finished product. Test it against the
criteria, watch where it fails, and improve one thing at a time. A
prototype that fails a test is not a failure of the learner; it is
exactly what prototypes are for.

**Worked example 1 — defining the latch problem:**

> Adult shows a box whose lid pops open when tipped. Adult narrates:
> "Need: the lid pops open. Defined problem: *design a magnet latch
> that keeps this box shut when tipped, but lets an adult open it with
> one hand.* Criteria: (1) stays shut upside down, (2) opens with one
> hand, (3) uses only the allowed materials. Constraints: two magnets
> at most, tape and string only, no glue. Now I can build and test —
> before this sentence, I could only guess."

**Worked example 2 — testing and improving:**

> Adult tapes one magnet to the lid and one to the box, opposite poles
> facing, and tips the box: the lid stays shut — criterion 1 passes.
> An adult pulls with one hand: the lid opens — criterion 2 passes.
> Then the adult tips the box hard, twice: on the second tip the lid
> pops open. Adult narrates: "The test found a failure point: a hard
> tip beats one magnet pair. Improvement: add the second magnet pair,
> or move the magnets closer to the lid's edge. I change **one**
> thing, then test again — the same fair-test rule as every
> investigation in this unit."

Key idea to say plainly: **Define the problem, write testable
criteria, name the constraints, build a prototype, test it, and
improve one thing at a time.**

## Guided practice (adult coaches)

1. Learner states the latch problem in one sentence, with the adult
   scribing if needed, and checks it names the job and the tool.
2. Learner picks three criteria from a list the adult reads aloud
   (including two that are not testable, such as "be nice") and
   explains why the untestable ones are rejected.
3. **Error-analysis:** Adult says, "My criteria are: use magnets, be
   good, and be fast." Learner explains what is wrong with each.

## Independent practice

4. Write or dictate the defined problem, three criteria, and two
   constraints for the no-touch keeper: a device that keeps two toy
   cars from touching when they roll toward each other.
5. Sketch the latch prototype: label where each magnet goes and which
   poles face each other (attract for a latch).
6. Name one fair test for the latch and what "pass" looks like for
   each criterion.
7. Answer: "Your prototype fails when the box is tipped hard. Do you
   change three things at once, or one thing? Why?"

## Application

Keeper challenge: the learner designs (on paper only, in this lesson)
a no-touch keeper for two rolling toy cars, using repelling poles.
The sketch must show the magnets, the poles facing, and the gap the
keeper keeps between the cars. Building happens in the project
session.

## Exit check

Adult asks: "What are criteria, and why must they be testable?"
Learner answers in one or two sentences, giving one latch criterion
as an example.

## Supports and extensions

- **Support:** the adult reads criterion options aloud; the learner
  points to the testable ones. Sketching may replace writing.
- **Alternate response mode:** dictate the problem sentence and
  criteria; build the sketch with magnet pieces on the table instead
  of drawing.
- **Extension:** add a cost constraint ("each magnet costs 1 token;
  you have 3 tokens") and a size constraint ("must fit in a box 10 cm
  wide"). Does the design still pass? What changes?

## Teacher note

Likely misconception: "criteria are wishes" ("be the best latch").
Criteria must be checkable by a test, or they cannot guide
improvement. Another slip: treating the first build as final — the
project rubric rewards a tested improvement, not a first-try success.
