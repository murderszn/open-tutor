# Project — Two Plans, One System

**Time:** Sessions 12 and 14 (plus at-home drafting) · **Materials:**
notebook, pencil, graph paper (or Desmos for checking graphs), the
two-food-trucks illustration from Lesson 06 if it helps you picture
your plans.

## The task

You run a small business — or you offer a service such as tutoring,
bike repair, or streaming lessons. Design **two pricing plans** for
the same service, then answer the question a customer would
actually ask: *when does each plan win?* Then test your skills on a
set of real-looking data, and build the two edge cases: plans that
never tie, and plans that always tie.

Your project must contain:

1. **Two plans, clearly priced.** Each plan has a fixed part
   (possibly $0) and a per-unit part. Name the service, the unit
   (meal, hour, session, gigabyte — your choice), and both prices.
   Write the system: let the variable stand for the number of
   units, let `C` stand for the cost in dollars, and write both
   cost equations.
2. **The break-even point, found two ways.** Solve the system by
   graphing (sketch both lines on graph paper, or check with
   Desmos) *and* by algebra (substitution or elimination). Both
   methods must give the same point. Check the point in both
   original equations.
3. **A recommendation.** For a small user, a medium user, and a
   large user (pick three unit counts — one below the break-even
   point, one at it, one above it), compute both costs in a table
   and say which plan wins each time and why. State the break-even
   point in a customer-facing sentence.
4. **The data-table test (fictional practice data).** A fair
   organizer recorded what two food trucks would charge for a day:

   | Meals sold | Red truck daily cost | Teal truck daily cost |
   |---|---|---|
   | 0 | $10 | $25 |
   | 5 | $30 | $30 |
   | 10 | $50 | $35 |

   The numbers in this table are fictional practice data, made up
   for this project. Use them to: (a) write the cost equation for
   each truck; (b) write the system and solve it; (c) say after how
   many meals the trucks' daily costs are equal and what that cost
   is; (d) say which truck is cheaper on a 12-meal day, with the
   numbers.
5. **Two variant pairs.** Using the same service as Part 1, write:
   - a pair of plans that **never** cost the same (no solution), and
   - a pair of plans that **always** cost the same (infinitely many
     solutions).
   Show the solving steps that prove each classification, and write
   one sentence explaining each variant in plain language.
6. **A presentation.** One page (written, poster, or spoken with
   notes) that a customer could follow: the two plans, the
   break-even point, the three-user table, and the recommendation.
   Include the data-table test and the variant pairs as a short
   "edge cases" note.

## Steps

**Session 12 — Invent and solve.**

1. Choose your service and unit. Write both plans as a two-column
   table (plan / fixed part / per-unit part).
2. Write both cost equations and the system.
3. Solve it by graphing and by algebra; confirm both methods agree.
4. Build the three-user table and draft the recommendation sentence.

**Between sessions — Draft.**

Work the data-table test and the variant pairs. Draft the
presentation page.

**Session 14 — Test, classify, and present.**

1. Finish the data-table test and the variant proofs with
   plain-language explanations.
2. Present your page to the adult. Answer one "what if" question:
   the adult changes one price — recompute the break-even point on
   the spot (or explain why the classification changes).
3. Revise one sentence of your recommendation based on feedback.

## Deliverables

- Plan table with prices and units named, and the system of two
  cost equations.
- Break-even point found by graphing and by algebra, with checks in
  both original equations.
- Three-user cost table and recommendation sentence.
- Data-table test: both cost equations, the system, the solution,
  and the 12-meal comparison.
- Two variant pairs with solving-step proofs and plain-language
  explanations.
- One presentation page.

## Rubric

Total: 40 points (10 per criterion).

| Criterion | 10 — Strong | 7 — Solid | 4 — Developing | 1 — Starting |
|---|---|---|---|---|
| Correct system and solutions (10) | Both plans expressed correctly as a system; break-even solved by graphing and by algebra with the same point, verified in both equations | One method shown fully; the other sketched; small arithmetic slip caught by the check | System set up but a method missing or an unverified answer; equations mostly right | Equations do not match the plans, or no check |
| Data-table test (10) | Both cost equations correct from the table; system solved; break-even point and 12-meal comparison correct with numbers | One equation or one number off, but the method is right | Equations attempted; break-even point asserted without solving steps | Test missing or equations unrelated to the table |
| Interpretation (10) | Recommendation follows from the table for all three users; break-even sentence is customer-clear; 12-meal comparison is explained | Recommendation follows for most users; sentence mostly clear | Recommendation asserted without table evidence | No recommendation, or one contradicting the table |
| Classification of variants (10) | Both variant pairs correct, proved by solving steps, with plain-language explanations | One variant correct and proved; the other attempted | Variants present but classifications asserted without proof | Variants missing or both misclassified |

**Ready signals:** the break-even answer is the same by graphing
and by algebra and is verified in both cost equations; the
three-user table agrees with the recommendation; each variant's
final form (a false statement for no solution, a true statement
for infinitely many) is boxed and named.

**Re-teach moves:** if the break-even equation is set up backwards
(fixed and per-unit parts swapped), return to Lesson 06's two-column
table habit. If a variant proof stops before the variables disappear,
revisit Lesson 05's "solve until the variables are gone or alone"
rule. If the graph and the algebra disagree, re-check the graph's
intercepts first — a misplotted intercept is the usual cause.
